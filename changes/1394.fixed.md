An upload that sends no message for 120 s ends with `DEADLINE_EXCEEDED`
and frees its upload slot, where it used to hold the slot for the whole
600 s call timeout. A principal that reads whole repos and may write
none is refused before it takes an upload slot at all. A principal the
server cannot refuse before its first message - one with a write rule
somewhere, no rule for any repo, or folder read rules - keeps its
documented answer and may still hold a slot for up to 120 s per stream
and open the stream again; `--max-principal-requests` is the limit for
that. The upload memory floor is unchanged: the permit still covers
exactly the reads in flight, one message each.
