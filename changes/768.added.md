A rejected land now answers why it can never succeed as a typed value.
`LandResponse.reject_reason` (field 6) carries one `LandRejectReason`
value when the state is `REJECTED`: `NEEDS_ONE_PARENT`,
`MISSING_REF`, `BASE_NOT_ON_HISTORY` or `ABANDONED` (the land stayed
pending past its deadline, so the stale-land sweep stopped it);
`UNSPECIFIED` for every other state. `UNSPECIFIED` on a `REJECTED`
land means no reason was given: the server that rejected it was older
than this field, or the row predates it - read `detail`. `detail`
stays, for people; the new field is the one a program matches on.
`GetLand` carries the reason too: it is stored with the land
(migration 0006) and read back with the rest of the outcome.
