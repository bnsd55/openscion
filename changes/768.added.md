A rejected land now answers why it can never succeed as a typed value.
`LandResponse.reject_reason` (field 6) carries one `LandRejectReason`
value when the state is `REJECTED`: `NEEDS_ONE_PARENT`,
`MISSING_REF` or `BASE_NOT_ON_HISTORY`; `UNSPECIFIED` for every other
state. `detail` stays, for people; the new field is the one a program
matches on. `GetLand` carries the reason too: it is stored with the
land (migration 0006) and read back with the rest of the outcome.
